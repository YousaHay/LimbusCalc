# 计算规则（MVP v0.1）

本文件记录计算器当前实现的公式、取舍与待验证项。代码中的唯一实现位于
`lib/features/calculator/domain/`，UI 只负责展示。

## 1. 计算范围

**计算：** 普通攻击技能在**指定硬币正反面结果**下，每次命中的直接伤害，以及整个技能的直接伤害合计。

**默认假设：**

- 技能已进入攻击阶段；所有输入的硬币均保留并命中同一目标。
- 攻击期间目标抗性、攻防等级及增减伤参数保持不变（整个技能共用一组乘区）。
- 不模拟拼点过程、目标死亡、混乱阈值跨越及命中后状态变化。

**不计算（视为不参与）：**

- 追加伤害（Attack Adder）、HP 追加伤害、固定追伤、按体力或已造成伤害计算的追伤。
- 状态伤害（烧伤、流血、破裂等）。
- 被动、状态效果、共鸣的自动解析；人格 / E.G.O / 饰品数据。
- 硬币重投、重复使用、不可摧毁硬币等特殊硬币。
- 自定义暴击倍率（E2 / E3 项）。
- 拼点胜率、精神值概率、伤害期望、多回合模拟。

## 2. 第一步：每次命中的当前威力

`domain/coin_power_calculator.dart`

```
current = 基础威力
对第 i 枚硬币（按投掷顺序）：
    before_i = current
    若正面：current += 硬币威力（带符号整数，加算为正，减算为负）
    若反面：current 不变
    after_i  = current          ← 第 i 次命中使用的当前威力 P_i
```

- 此前硬币产生的累计变化会影响后续命中。
- 合计伤害 = 逐次命中伤害之和，**不是**“末枚威力 × 硬币数量”。
- 第一版所有硬币使用同一个硬币威力值。
- 本函数不对威力做任何上下限处理。

### 威力边界（未确认）

当**基础威力 ≤ 0** 或**任一命中威力 ≤ 0** 时，本版**不输出确定伤害**，只展示威力序列并提示原因。

理由：所查资料均未说明以下问题——

1. 威力降至 0 或负数时是否被钳制（例如钳制为 0）；
2. 若钳制，钳制后的值是否参与后续硬币的累计；
3. 威力为 0 的命中是否仍按保底造成 1 点伤害。

社区资料中出现过“拼点威力不会为负、按 0 处理”的说法，但那是**拼点**威力，
不能直接推出命中伤害所用威力的处理方式。另需注意：“伤害至少为 1”是伤害保底，
不等于“当前威力至少为 1”。

## 3. 第二步：每次命中的直接伤害

`domain/damage_calculator.dart`

```
d  = 最终攻击等级 − 目标防御等级

resistanceBonus(r):
    r ≤ 0        → −0.5
    0 < r < 1    → (r − 1) / 2
    r ≥ 1        → r − 1

A = resistanceBonus(有效罪孽抗性倍率)
B = resistanceBonus(有效物理抗性倍率)
C = d / (|d| + 25)
拼点 = 拼点轮数 × 0.03
暴击 = 暴击 ? 0.2 : 0

staticFactor  = max(1 + A + B + C + 拼点 + 暴击, 0)
dynamicFactor = 1 + 进攻方动态修正 + 受击方动态修正

rawDamage     = P × staticFactor × dynamicFactor
minimumDamage = max(1, P × 0.05)
coinDamage    = floor(max(rawDamage, minimumDamage))

skillDamage   = Σ coinDamage
```

要点：

- 抗性修正与攻防等级修正属于**同一个静态乘区**，相加而不是分别相乘。
- 暴击基础加成 0.2 **进入静态乘区**，不是对最终结果额外 ×1.2。
- 进攻方与受击方的动态修正在**同一动态乘区相加**。UI 以百分数输入，内部除以 100 转为小数。
- **每次命中独立**进行保底比较与向下取整，再求和；不先求和再取整。
- 保底判断 → 向下取整的顺序固定在 `calculateHit` 中，UI 不参与。
- 动态乘区本版未设下限；若其为负，原始伤害为负，结果由保底决定。

### 输入解释

| 输入 | 含义 |
|---|---|
| 最终攻击等级 | 已计入外部修正后的**技能**攻击等级，不是角色等级 |
| 抗性倍率 | 本次攻击实际使用的倍率；不自动处理混乱或抗性覆盖 |
| 拼点轮数 | 0 表示未经拼点的单方面攻击 |
| 暴击 | 第一版统一应用于所有命中 |

### 输入限制（产品层面，非游戏机制）

| 字段 | 类型 | 范围 |
|---|---|---|
| 基础威力 | 整数 | −999～999（≤ 0 触发边界提示） |
| 硬币数量 | 整数 | 1～10 |
| 硬币威力（绝对值） | 整数 | 0～999 |
| 攻击 / 防御等级 | 整数 | 0～999 |
| 抗性倍率 | 小数 | −10～10 |
| 拼点轮数 | 整数 | 0～99 |
| 动态增减伤 | 小数（%） | −1000～1000 |

只接受普通十进制写法；空值、非法字符、科学计数法、NaN、Infinity 均被拒绝。
任一字段非法时不产生结果，页面不会继续显示旧结果。

## 4. 精度策略

- 使用 Dart `double`（64 位）计算，**不主动截断任何中间结果**。
- 参考资料指出游戏内部使用 32 位浮点。本版**不保证与游戏逐位一致**；在恰好落在整数边界附近的输入上，结果可能与游戏相差 1。
- 不通过随意添加 epsilon 掩盖浮点误差。
- UI 显示最多保留 4 位小数（攻防等级修正 C 显示 6 位），格式化只用于显示，不回写计算值。

## 5. 已知差异与待验证项

### 5.1 攻防等级修正是否截断至两位小数（待验证）

| 规则 | 来源 | C(1) | 示例：d = 1，P = 200 |
|---|---|---|---|
| **完整精度（本版采用）** | Syx 博客公式无截断步骤；灰机 Wiki 本次未能访问，据需求说明亦未明确截断 | 0.038461… | floor(207.69) = **207** |
| 向零截断至两位小数 | Skillary（以 wiki 表值 1→0.03、3→0.10、10→0.28、20→0.44、100→0.80 反推） | 0.03 | floor(206) = 206 |
| 与暴击等合并后四舍五入至两位 | MirrorCalcWeb（还原自 Excel 表格的 `ROUND(…, 2)`） | 0.04 | 视其他项而定 |

本版采用完整精度，原因：Syx 博客的公式没有截断步骤；Skillary 的结论是从展示表的数值反推的，
而展示精度不一定等于内部计算精度。三套规则互不混用。
测试 `damage_calculator_test.dart` 中“【本版规则】完整精度”用例锁定当前选择，
若日后经实测确认截断规则，应同时修改 `levelBonus` 与该用例。

### 5.2 其他待确认

- 威力 ≤ 0 时的游戏行为（见第 2 节）。
- 保底 `0.05 × P` 与最终取整的先后：Syx 博客未说明顺序；本版按“先比较保底、再整体向下取整”实现，与 Skillary 的描述（“结果向下取整，且不低于 1 或硬币威力的 5%”）一致。
- 动态乘区是否存在下限。
- Syx 博客将罪孽抗性分段写为 `x < 0 → −0.5`、`0 ≤ x < 1 → (x − 1)/2`；在 x = 0 处两者都得到 −0.5，与本版 `r ≤ 0` 的写法结果相同。
